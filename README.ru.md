# Обзор проекта

Этот репозиторий содержит реализацию процессора событий подземелья на Go. Программа читает временные события, обновляет состояние игроков, выводит лог и формирует финальный отчёт.

---

# Структура проекта

- **main.go** — точка входа CLI.
- **engine** — пакет с логикой: парсер, обработчики событий, формирование отчёта, тесты.
- **data** — пример входных данных: `config.json` и `events`.
- **Makefile** — цели для сборки, запуска и тестирования.
- **go.mod** — модуль Go.

---

# Принцип работы алгоритма

**Кратко**  
Процессор принимает последовательность строк‑событий вида `[HH:MM:SS] <player_id> <event_id> [params]`, применяет события к состоянию игроков и генерирует лог и финальный отчёт.

**Основные сущности**
- **Config** — параметры: количество этажей, монстров на этаж, время открытия и длительность.
- **Player** — состояние игрока: регистрация, внутри/вне подземелья, HP, текущий этаж, времена входа/выхода, времена очистки этажей, времена босса, флаги смерти/дисквалификации.
- **Event** — одна строка входа: временная метка, id игрока, код события и необязательный параметр.

**Поддерживаемые события**
- `1` — регистрация
- `2` — вход в подземелье
- `3` — убит монстр
- `4` — переход на следующий этаж
- `5` — возврат на предыдущий этаж
- `6` — вход на этаж босса (forgiving режим: принудительный переход)
- `7` — убийство босса
- `8` — выход из подземелья
- `9` — не может продолжать → дисквалификация
- `10` — восстановление HP (параметр — значение)
- `11` — получение урона (параметр — значение)

**Ключевые правила**
- События до регистрации приводят к дисквалификации.
- Вход до открытия или после закрытия — дисквалификация.
- После смерти или дисквалификации последующие события (кроме регистрации) игнорируются.
- В режиме «forgiving» событие `6` переводит игрока на этаж босса даже если он не прошёл все этажи.
- Время очистки этажа фиксируется при убийстве последнего монстра на этом этаже.
- Финальный отчёт содержит статус игрока (`SUCCESS`, `FAIL`, `DISQUAL`), общее время в подземелье, времена по этажам и HP.

# Формат входных данных

**config.json** пример:
```json
{
  "Floors": 2,
  "Monsters": 2,
  "OpenAt": "14:05:00",
  "Duration": 2
}
```

**events** пример строки:
```
[14:10:00] 2 2
```
Где:
- `[HH:MM:SS]` — временная метка
- `2` — id игрока
- `2` — код события
- далее опционально параметры

# Сборка и запуск

**Сборка**
```bash
go build -o dungeon .
```

**Запуск с примерными данными**
```bash
cp -f data/config.json config.json
./dungeon < data/events
rm -f config.json
```

**Makefile цели**
```bash
make build   # собрать бинарь
make run     # запустить ./dungeon < data/events
make test    # запустить все тесты
make clean   # удалить бинарь
```

---

# Тестирование

```bash
go test ./...
```

Тесты покрывают интеграционный сценарий и ключевые инварианты:
- обработка смерти и игнорирование последующих событий;
- правила дисквалификации;
- учёт времени очистки этажей и времени босса.
